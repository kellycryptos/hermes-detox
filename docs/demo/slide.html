The Problem

Context Flooding & The Middle-Cut Trap

Why standard truncation breaks agent reasoning and creates permanent blindness.

01 / Context Flooding
Test suites, build logs, and API payloads frequently dump 10,000–30,000 tokens into conversation history. This consumes over 70% of context, degrading reasoning and forcing premature compaction.
02 / The Lossy 50k Cut
In standard Hermes Agent, terminal output exceeding 50,000 characters is aggressively sliced by keeping 40% head and 60% tail. The middle section is erased forever before the LLM sees it.
03 / Root Causes Amputated
Stack traces, assertion diffs, and core error logs typically sit in that destroyed middle chunk. No tool can bring them back, causing the agent to hallucinate or fail tasks.

Architecture

Dual-Hook Diagnostic Firewall

Intercepts before lossy truncation, preserves full text, and feeds compact reports to the model.

Interception & Archival Pipeline:
1. transform_terminal_output captures stdout before the 50k cap.

2. Local SQLite WAL (detox.db) archives full text securely with POSIX 0700/0600 permissions.

3. 6 Content-Aware Extractors parse Pytest, GCC/Clang, Tree listings, JSON, and server logs.

4. 0.55 Compression Gate delivers the report only if it cuts ≥45% of noise; otherwise fails open untouched.
On-Demand Agent Retrieval:
5. Model receives compact diagnostic report with exact 1-based line numbers and unique Evidence ID.

6. Model calls detox_inspect(id, start_line, end_line) to pull exact lines in 0.16 ms.

7. Model calls detox_search(query, id) to scan stored outputs.

8. User monitors savings anytime via /detox status.
